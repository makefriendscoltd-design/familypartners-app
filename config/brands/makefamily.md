# 메이크패밀리 브랜드 보이스

## 정체성
- AI로 사업을 키우는 1인 사업가·대표들의 '함께 성장하는 파트너'.
- 슬로건 정서: "혼자 가면 빠르지만, 함께 가면 크게 간다."
- 소비자가 아니라 생산자를 만든다.

## 톤
- 단정적이고 직설적. 군더더기 없음. 실행을 압박한다.
- 따뜻하지만 냉정한 면 공존("하루라도 안 하면 강퇴" 같은 기준).
- 추상적 동기부여보다 구체적 숫자·사례·기준으로 말한다.
- 과장된 미사여구·이모지 남발 금지. 짧은 문장, 줄바꿈으로 호흡.

## 자주 쓰는 프레임
- "어?" 테스트(읽는 사람이 멈칫하는 후킹).
- 노출량 게임 — 하루 한 번이 쌓여 매출이 된다.
- 배우고 → 만들고 → 판매하고 → 함께 성장.
- 1인칭 경험과 성과는 사용자 원문으로 확인된 경우에만 쓴다. 경험·시간 절약·매출 수치를 만들어내지 않는다.

## 금지
- 공허한 동기부여("당신은 할 수 있어요"류).
- 추천인 다단계 느낌의 표현.
- 클릭베이트성 거짓 과장.

## 타깃
- AI를 배우고 콘텐츠로 사업을 키우려는 대표·예비창업자.

## 파트너스 무료자료형 — 2026-09-22 사용자 확정

문체·구성의 기준은 운영 글감 피드의 제목 번호 **컨텐츠 1~30**이다. DB 행 ID 1~30이 아니다. 사용자가 직접 쓴 글이 많은 이 묶음을 먼저 읽고 쓴다. 원본은 보존한다.

실제 원문 첫 문장:
- 컨텐츠 1: “나 AI 회사 만들고 있음”
- 컨텐츠 4: “기록 많은 사람은 무조건 하세요”
- 컨텐츠 5: “돈없고 빽없으면 AI 직원부터 만드세요”
- 컨텐츠 19: “AI 직원한테 맡길 수 있는 업무들”
- 컨텐츠 30: “AI 직원이 일 못하는 이유 5가지”

첫 문장에서 대상·맡길 업무·해보고 싶은 결과 중 하나가 바로 보여야 한다. 추상적인 문제 제기나 자료 소개로 시작하지 않는다. 본문에는 영업시간 안내, 예약 답변, 회의에서 결정한 일처럼 눈에 그려지는 일을 쓴다. 활용 목록·직접 제안·질문을 주제에 맞게 고르며 모든 글을 같은 틀에 넣지 않는다.

짧은 줄, 의미 단위의 빈 줄, 말하듯 쓰는 문장이 우선이다. 번호 목록은 원문에도 있는 실제 활용을 보여줄 때 쓴다. 안내문처럼 격식을 올리거나 반말을 기계적으로 붙이지 않는다. “실패 경험 → 몇 분 만에 해결 → 자료 있어요”를 반복하지 않는다.

무료자료형은 실제 제공 자료명과 댓글 키워드로 끝낸다. 원본 30개 전부가 자료 배포형인 것은 아니므로 말투를 참고하되 현재 배포 목적의 CTA는 유지한다. 기존 글 수정 때 날짜·제목·자료 코드·키워드는 보존한다.

정본: 글감은 `config/drops_queue.json`, 자료는 `config/assets.json`. 가독성 수치는 `deploy/lint_drops.py`를 따른다. 숫자나 도구명을 넣으려고 없는 성과·시간 보장을 만들지 않는다. 제출 전 실제 초기 원문과 비교하고, 설치된 최신 humanize-korean으로 의미 보존·변경률을 확인한다. 검사기 통과는 후킹이나 조회수 향상의 증거가 아니다.

## 2026-10-19 글감 품질 수정 — 최신 기준

- 위 초기 원문은 말투 참고다. 파트너 자신의 경험으로 확인되지 않은 1인칭·동료·고객 사례를 복제하지 않는다. "나는 둘 다였는데", "옆자리 후배는" 같은 인물을 만들어 반복하지 않는다.
- 구체적인 불편이나 하고 싶은 일로 시작하고, 본문에 바로 써볼 질문·작업 순서·비교 기준 중 하나를 남긴다. 도구 이름과 자료 신청만으로 본문을 채우지 않는다.
- 정보·의견 글에는 숫자와 댓글 유도를 강제하지 않는다. 자연스러운 질문이나 실천 제안으로 끝내도 된다. 무료자료형은 실제 자료와 기존 신청 키워드를 유지한다. 숫자·성능·수익을 후킹용으로 지어내지 않는다.
- 각 글의 줄 수·길이는 기존 검사 기준을 지킨다. 하루치의 첫 문장과 끝맺음을 함께 읽고 같은 표현·구조를 반복하지 않는다. AI 결과를 보장하거나 검토 없이 사용하라고 하지 않는다.
- 글감 복사만으로 실제 경험처럼 보이는 문구는 제거한다. 경험담이 필요하면 확인된 실제 경험을 별도로 받아 작성한다.
- 조회수가 높아질 것이라는 보장은 하지 않는다. 문체 검사와 실제 게시 성과를 구분한다.

## 2026-10-19 예약 글 후킹 — 사용자 승인 예시

- 승인한 첫 문장: “코덱스로 홈페이지만 만들고 끝내면 아까움.” 이미 하는 일을 짚고 놓치고 있는 활용을 궁금하게 만든 뒤, 다음 줄에서 구체적인 결과나 실행할 내용을 보여준다.
- “소개영상도 뽑으세요”, “살펴볼 만한 프로젝트예요” 같은 일반적인 권유·도구 소개로 시작하지 않는다. 원문 사실과 자료가 뒷받침하는 내용만 약속한다.
- 모든 글을 “아까움”으로 복제하지 않는다. 대상 직접 호명, 구체적인 막힘, 놓친 활용 등 주제에 맞게 첫 문장을 바꾼다. 짧은 구어체와 의미 단위 줄바꿈을 유지한다.
- 실제 결과 화면이나 경험이 없는 도구를 직접 사용한 것처럼 쓰지 않는다. 후킹 다음에는 본문에서 약속한 내용을 바로 보여주고, 자료명·신청 키워드는 정확히 보존한다.
- 10월 6일 makefamily_ 인사이트 저장본에서 직접 호명 뒤 구체적인 결과를 제시한 글과 결과가 모호한 글의 성과 차이를 확인했다. 이는 작성 가설의 근거이며 문구만의 인과효과나 조회수 보장이 아니다.

## 최신 소재 수집부터 작성 — 2026-10-19 사용자 확정

1. 매 작성 작업마다 `deploy/collect_drop_sources.py`로 공식 소식 후보와 라운지의 현재 공개 자료 목록을 새로 읽는다. 수집 범위·공식 피드·라운지 URL의 정본은 `config/assets.json`의 `_research`다. 피드는 시작점이며 Agent Reach로 커뮤니티 사례와 추가 공식 원문을 찾는다.
2. 원문 발행·업데이트 날짜와 수집일을 따로 기록한다. 오래된 저장소를 오늘 발견한 것, 라운지의 동기화 시각, 검색엔진 수집일을 신제품 출시일처럼 쓰지 않는다. 최신이라고 쓸 근거가 없으면 최신 표현을 뺀다.
3. 도구 소개를 위해 소재를 고르지 않는다. 독자에게 보일 구체적인 결과·시연·활용을 먼저 찾고 원문을 읽는다. 공식 소스의 주장과 직접 검증한 사실을 구분하고, 필요한 주장에는 content-research-gate를 적용한다.
4. 채택한 글은 큐 항목의 `sources`에 원문 URL·제목·`published_at`(불명확하면 null)·`collected_at`·`verified_at`을 남긴다. 작업 산출물에는 원문 스냅샷과 팩트팩을 보관한다. 링크 없이 최신 글이라고 등록하지 않는다.
5. 현재 라운지 정본은 `/worldclass`의 **AI 활용노트**다. `무료 자료`와 `해외 사례`를 매번 조회해서 신규 항목을 찾고, 예전 `/resources` 목록을 현재 자료실 전체로 취급하지 않는다. 이름만 읽고 본문에 없는 기능을 약속하지 않는다. 상세 본문을 읽고 관련성이 확인되면 기존 `assets`의 코드에 `lounge_slug`와 `lounge_url`을 연결한다. 새 자료는 본문 확인 후 실제 이름·코드로 등록한다. 해외 사례를 다운로드 가능한 무료 자료로 약속하지 않고, 로그인 필요를 숨기지 않는다.
6. 자료가 연결되는 글에만 자료 신청 문구를 넣는다. 관련 자료가 없으면 정보글로 끝내고, 앞으로 만들 자료를 이미 받을 수 있는 것처럼 약속하지 않는다. 단순히 비슷한 제목이라는 이유로 연결하지 않는다.
7. 사용자 승인 후킹으로 작성 → humanize-korean → 기존 검사 → 운영 반영 범위 검증 순서다. 수집 실패 시 기존 소재를 최신으로 포장하지 않고, 미확인 원문·본문은 미검증으로 남긴다. 기존 발행·예약 시각은 이 절차만으로 바꾸지 않는다.

## 2026-10-19 본문·댓글 복사 위치 정정

- 복사 UI는 **파트너스 글감방·오늘 글감·관리자 미리보기**에 둔다. 라운지는 사례와 무료자료의 출처이며 복사 기능을 추가하는 대상이 아니다.
- 사례형 글감 정본은 drops_queue.json의 body(후킹 본문), replies(번호를 포함한 사례 댓글 배열), link_comment(마지막 라운지 링크 댓글)다. 실제 사례 내용은 댓글에 순서대로 쓰고 링크만 나열하지 않는다.
- 별도 검토한 추가 사례는 supplemental=true로 표시한다. 정규 예약 4건을 대체하지 않으며 개별 글 품질 검사는 동일하게 받는다.
- 게시 후 본문을 관리자에서 바꾸면 기존 댓글은 숨긴다. 수정한 본문과 댓글을 큐에서 함께 맞춘 뒤 반영한다.
