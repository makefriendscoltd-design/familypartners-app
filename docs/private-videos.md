# 파트너 영상 배포

관리자 `/op/videos`에서 제목과 MP4 원본을 등록하고, 확인 후 공개한다.
파트너는 내 작업실의 ‘영상 받기’에서 등록 이름을 입력한다. 선착순 한 명에게
배정하며, 다른 파트너 목록에서는 사라진다. 열어 둔 카드 목록은 2.5초마다 갱신한다.
동시에 눌러도 DB 조건부 UPDATE로 한 명만 배정한다.

다운로드 요청 시점에 배정한다. 브라우저의 저장 완료 여부는 판단하지 않는다.
연결이 끊겨도 같은 활성 계정은 ‘내가 받은 영상’에서 다시 받는다.
일시정지·강퇴 계정의 접근은 기존 포털 정책대로 차단한다.
관리자는 수령 당시 이름과 시각을 확인한다. 계정 삭제 후에도 이 기록과
배정 상태는 보존하며, 다른 사람에게 다시 배포하지 않는다.

원본은 공개 자료실이나 Git에 넣지 않는다. SQLite 전용 서버의
`data/private_videos/`(또는 `FP_VIDEO_DIR`)에 저장한다. 최대 512MB MP4,
동일 SHA256 파일은 중복 등록하지 않는다. DB와 비공개 파일 디렉터리를
함께 백업해야 한다. 외부 정적 파일 서버에 이 디렉터리를 연결하지 않는다.
PostgreSQL/서버리스 업로드는 지원하지 않는다.

검증: `python3 -m unittest discover -s tests -p test_video_library.py -q`
테스트는 임시 DB/파일과 직접 생성한 HTTP 서버를 사용한다.
운영 watchdog 또는 문자 발송은 실행하지 않는다.

대시보드와 영상 목록은 실제 영상 썸네일 카드로 표시한다. 카드 선택만으로는
배정하지 않으며, 이름을 입력하고 수령 버튼을 눌러야 배정한다.
새 관리자 업로드는 브라우저에서 JPEG 썸네일도 자동 추출한다. 썸네일은
비공개 원본 옆에 저장하며, 미배정 공개 영상 또는 수령자/관리자에게만 제공한다.

영상별 캡션은 DB `video_captions`가 정본이다. 관리자 영상 배포 화면에서
편집하며 원본 SHA 확인 후 저장한다. 스크립트의 핵심 내용을 유지하고
구독/프로필 안내를 댓글 키워드 CTA로 바꾼다. 새 영상 배포 때 캡션도 함께 등록한다.
수령 직후와 ‘내가 받은 영상’에서 캡션을 복사할 수 있다. 기존 수령자에게도
업데이트된 캡션이 표시되며, 미수령자에게는 캡션 원문을 제공하지 않는다.

신규 수령 한도는 `fp/video_library.py`의 `DAILY_VIDEO_LIMIT`가 정본이다.
계정당 한국 시간 기준 하루 3편이며, 자정에 초기화한다. 기존 수령 이력도
포함한다. 이미 받은 원본/캡션을 다시 받는 것은 한도를 소비하지 않는다.
SQLite는 BEGIN IMMEDIATE, PostgreSQL은 계정 행 잠금으로 한도 확인과
배정을 한 트랜잭션에서 처리해 서로 다른 영상의 동시 선점을 막는다.
기존 배정은 회수하거나 다른 계정으로 옮기지 않는다.

## 완성 쇼츠 자동 등록

`config/partner_video_sync.json`이 수집 대상의 정본이다. 요청한 제작 세션의
10개 source ID만 명시한다. 다른 세션·다른 날짜의 출력은 추측해서 추가하지 않는다.
이 목록의 미완성 영상은 다음 실행에서 다시 확인한다. 후속 제작 배치가 생기면
이 정본에 해당 경로를 추가해야 한다. 제작 세션·YouTube 게시 작업은 실행하지 않는다.

`deploy/sync_partner_videos.py`는 5분 간격의 별도 macOS launchd 잡으로 실행한다.
정본 설정의 `auto_discover`가 있으면 `sources` 목록에 더해 `root/pattern`(예: `navercafe/outputs/*/shorts`)에서
새로 렌더된 숏폼을 찾아 같은 검사를 거쳐 대기열에 올린다. `max_age_days`가 지난 렌더는 사람이 확인해야 하므로 건너뛰고,
처음 올리는 건은 한 번 실행에 `max_per_run`개까지만 처리한다. 이미 올린 원본은 `final.mp4`의 수정시각·크기가
그대로면 다시 해시하지 않는다.
`cutback_jobs`가 있으면 cutback 롱폼숏폼화 도구의 `jobs/<id>/out/cNN.mp4`도 찾는다. `meta.json`의 원본 채널이
`channels` 허용 목록에 있을 때만 올리고(국내 남의 채널·AI 무관 영상 금지, 2026-09-21), 세로 16:9·소리·3분 이하·
헤드카피 한 줄 920px 이하를 확인한다. 제목과 캡션은 `plan.json`의 `head1`/`head2`/`title`로 만든다.
Mac이 켜져 있고 네트워크가 연결되어야 수집되며, 복귀 후 다음 실행에서 따라잡는다.
AI 호출 없이 파일 검사와 HTTPS만 사용한다. 중복 실행은 파일 잠금으로 막는다.

render/visual/machine 검사 pass와 최종 MP4 해시, production_manifest의 입력·대본·CTA
해시를 모두 대조한다. 캡션은 대본의 핵심 항목만 짧게 추리고 댓글 키워드를 바꾸지 않는다.
원본을 별도 임시 파일로 복사한 후 해시를 다시 확인한다. 비공개 등록 → 원본 다운로드
해시 대조 → 실제 영상 프레임 JPEG 생성/업로드/해시 대조 → 캡션 원문 대조 → 공개
순서다. 동일 해시는 중복 등록하지 않고 이미 공개·배정된 영상은 건드리지 않는다.
원본이 다른 해시로 바뀐 경우 자동 재배포를 보류한다.

인증은 관리자 `/op/videos`에서 얻는 목적별 `video-sync-token`을 사용한다.
토큰은 `~/.local/share/familypartners-video-sync/token`에 권한 600으로만 저장한다.
파트너·일반 관리자 화면은 이 토큰으로 접근할 수 없다. 업로드·검증·공개 API만 허용한다.
FP_SECRET 변경 시 토큰을 다시 받아야 한다. 인증 실패는 다음 주기에 재시도한다.
토큰·고객 이름·캡션 원문은 상태 로그와 공통 CRM 장부에 남기지 않는다.

로컬 운영 상태는 같은 디렉터리의 `state.json`과 `stdout.log`, `stderr.log`를 확인한다.
공개 응답을 잃어도 서버 상태를 먼저 조회하며 재공개하지 않는다. 공개 성공을 확인한 뒤
CRM에 채널·캠페인·단계·건수만 기록한다. 기록 실패는 중복방지 키로 재시도한다.

검증: `python3 -m unittest discover -s tests -p 'test_*video*.py' -q`

비파괴 사전 확인:

```
python3 deploy/sync_partner_videos.py --config config/partner_video_sync.json --state-dir ~/.local/share/familypartners-video-sync --dry-run
```

실제 등록은 위 명령에서 `--dry-run`을 뺀다. 수령 테스트를 운영 계정으로 실행하지 않는다.

macOS 보호 폴더의 촬영 원본은 최초 연결 시 해시를 대조한 불변 복사본을
`input_snapshots` 디렉터리에 SHA256 파일명으로 보관한다. 예약 작업은 해당
렌더 입력의 복사본 해시를 검사한다. 대본·CTA·최종 MP4와 출력 디렉터리 안의
입력은 항상 제작 위치에서 직접 검사하며 복사본으로 우회하지 않는다.
새로운 외부 촬영 원본이 사용되면 그 해시의 복사본을 준비해야 한다.

검수에서 배포 제외한 원본은 같은 정본 설정의 `excluded_sha256`에 기록한다.
기존 배치를 다시 실행해도 이 해시는 업로드·공개 API를 호출하지 않는다.
공개 중인 미수령 영상은 관리 API로 비공개 전환한 뒤 실제 목록에서 빠졌는지
확인한다. 원본 보관 파일과 기존 배정 이력은 삭제하지 않는다.

인스타 복사용 캡션은 짧은 도입, 핵심 항목 최대 3개, 댓글 정리본 CTA 순서다.
길이 상한의 정본은 `deploy/sync_partner_videos.py`의 `CAPTION_MAX_CHARS`다.
CTA 공간을 먼저 확보하며 긴 문장을 중간에서 자르지 않는다. 영상의 댓글 키워드는
유지한다. 신규 자동 등록과 과거 배치 등록 모두 같은 함수를 사용한다. 기존 공개·수령
캡션 변경은 영상 재공개 없이 캡션 API로 저장하고 다시 읽어 대조한다.

## 디스크 정리

매일 자정 채우기 뒤에 영상 디스크 사용률을 본다. 80%를 넘으면 파트너가 받아간 지 14일 지난 원본부터
오래된 순으로 지워 70%까지 내린다. 아무도 안 받은 영상은 지우지 않는다. 배정 기록·캡션·썸네일은 남고, 파트너 화면에는
"보관 기간이 지나 원본을 정리했어요"가 뜬다(원본 요청은 410). 값은 `fp/video_library.py`의 `PURGE_*` 상수가 정본이다.
