# Threads 레퍼런스 분석과 적용

참고 URL: https://www.threads.com/@zero__gray/post/DdIq4iBiTRA
확인: 2026-10-23. Jina Reader로 본문, 작성자 대댓글 11개, 공개 독자 댓글을 읽음. 원문 스냅샷은 reference.txt. 화면에 표시된 날짜와 수치를 확인했으나 사례의 매출·인과 주장을 별도로 검증한 것은 아님. 문체만 참고함.

## 단어의 역할

원문은 감탄과 반말로 주의를 끌고, 분석했다는 동사로 정리해주는 사람의 위치를 잡는다. 실패를 일상어로 표현해 사업 사례의 거리감을 줄인다. 후반부에는 명령형 행동 동사로 독자가 할 일을 지정한다. 여기서 가져온 것은 생활어와 구체적인 행동 동사다. 과한 감탄, 목숨을 건다는 표현, 무조건적인 성공 일반화는 적용하지 않았다.

## 문맥과 구조

본문: 서로 다른 규모의 사람들에게 같은 순서가 있다는 궁금증 → 비교 대상의 범위 → 이어 읽을 약속.
대댓글 1: 비교 대상 소개. 2: 실패라는 배경. 3~7: 유통·첫 제품·자기 문제·플랫폼 의존·인력 운용의 공통점을 순서대로 주장. 8: 독자의 환경으로 연결. 9: 실행 목록. 10: 요약. 11: 실행 의향이 있는 독자를 외부 링크로 유도.

각 댓글은 하나의 주장 아래 구체적인 인물·행동을 놓고 짧은 해석을 붙인다. 다음 댓글은 새 논점을 보태므로 목록을 길게 쪼갠 것과 다르다. 다만 수치가 많은 글이라는 점, 자신 있게 단정한다는 점을 곧 사실성이나 성공 공식으로 취급하면 안 된다.

공개 독자 댓글에는 감사·저장 반응과 과장된 표현에 대한 반응이 함께 있었다. 이를 조회수의 원인이나 독자 전체의 평가로 단정하지 않는다.

## 현재 글에 적용한 것

대상: 10/23~26 AI 직원 추가분 컨텐츠 235~242, 8개. 정규 사례형 16개 등 나머지 65개는 보존. 날짜·제목·출처·자료 URL·게시 구조를 유지했다. 작성 기준은 config/brands/makefamily.md에 추가했다.

| 글 | 수정 전의 중심 | 수정 후의 읽는 순서 |
|---|---|---|
|235|맡길 일 선택을 권유|오늘 반복한 일 → 끝난 모습 정의 → 자료에 없는 질문 → 첫 업무 한 문장|
|236|업무지시 항목 나열|알아서 하라는 지시 → 답할 범위 → 실제 말투 예시 → 현재 지시서의 빈 항목|
|237|답장 기록 수집|오래된 안내가 섞인 장면 → 기록 정리 → 답할 범위 구분 → 없는 질문으로 확인|
|238|회의록 출력 항목|회의 뒤 다시 담당자를 찾는 장면 → 요청문 → 제안자/담당자 대조 → 다음 회의 활용|
|239|내 글을 예시로 제공|안 쓰는 말이 나오는 장면 → 비슷한 용도 글 → 직접 수정 비교 → 말투와 사실 분리|
|240|틀린 답에 피드백|다시 하라는 요청 → 오류별 자료 → 다른 질문으로 재확인 → 다음 점검 목록|
|241|업무를 단계별로 분리|조사부터 발송까지 맡기는 욕심 → 넘길 결과 → 틀어진 단계 찾기 → 발송 전 원고/대상 확인|
|242|업무에 사용 시점 지정|만들고도 직접 일하는 장면 → 넣고 받을 자료 → 빈 자료/중복/실패 확인 → 다음 실행 시점|

원고의 핵심 사실과 제안은 유지하면서 설명 댓글을 2개에서 3개로 확장했다. 모든 미래 글에 3댓글을 강제하는 규칙은 아니다. 자료 댓글은 8개 모두 같은 안내문이던 것을 각 글의 다음 행동에 연결했다. 원문의 문장이나 수익 사례를 파트너의 경험처럼 옮기지 않았다.

## 검토 범위

기존 원고와 초기 자사 원문 1~30을 직접 읽었다. 추가한 내용은 업무지시·대조·기록의 실천 예시이며 외부 성과 주장이 아니다. 레퍼런스의 사례 팩트를 재활용하거나 최신 커뮤니티 조사 완료를 주장하지 않는다.
재작성 후 humanize-korean 최신 quick-rules로 의미·격식·과장·번역투·문장 리듬을 점검한다. 검사 통과는 조회수 개선의 증거가 아니다. 실제 검사·배포 결과는 checkpoint.md와 validation.json에 기록한다.
