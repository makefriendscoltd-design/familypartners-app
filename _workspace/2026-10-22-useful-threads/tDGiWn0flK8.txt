경쟁사 조사부터 보고서 작성까지, AI에 맡길 업무를 설계하는 방법

경쟁사 소식을 확인해도 우리 사업에서 무엇을 바꿔야 할지 정리하기는 쉽지 않습니다. 상품과 가격을 찾아보고, 고객층과 홍보 문구를 비교한 뒤, 검토할 내용을 보고서로 묶어야 하기 때문입니다. 매번 조사부터 다시 시작한다면 정기적으로 이어가기도 부담스럽습니다.

영상에서는 Claude Code로 경쟁사를 조사하고 회사의 로고와 디자인을 반영한 PDF 보고서를 만드는 과정을 시연합니다. 사업자가 원하는 결과를 설명하면 AI가 필요한 절차와 도구를 구성하고, 실행 중 발견한 문제를 수정하는 방식입니다. 이 사례를 업무에 적용하려면 어떤 정보를 맡기고 어떤 결과를 확인할지부터 정리해야 합니다.

제작자는 반복적이고 예측 가능한 업무에는 n8n 같은 기존 자동화 도구가 여전히 적합하다고 설명합니다. 처리 순서와 전달할 값이 정해져 있다면 같은 절차를 안정적으로 반복하는 것이 중요하기 때문입니다.

경쟁사 조사는 단계마다 판단이 개입합니다. 어떤 회사를 경쟁사로 볼지, 수집한 정보에서 무엇을 비교할지, 우리 사업에 어떤 의미가 있는지 결정해야 합니다. 제작자가 설명하는 에이전트형 업무 흐름은 이런 변동성 있는 작업에서 AI가 지침을 읽고 도구를 선택하며 진행하도록 구성하는 방식입니다.

사업에 적용할 때도 이 구분부터 해보는 편이 좋습니다. 예를 들어 경쟁사 가격을 정해진 양식에 옮기는 일과, 가격 차이를 보고 우리 상품의 개선 방향을 제안하는 일은 필요한 판단의 범위가 다릅니다. 후자에는 비교 기준과 우리 사업의 상황을 함께 전달해야 결과를 검토하기 수월합니다.

영상은 작업을 정리하는 방법으로 WAT를 소개합니다. 업무 절차를 담은 워크플로, 진행을 조율하는 에이전트, 실제 작업을 수행하는 도구를 나눈 구성입니다. 업무를 맡기는 사업자 입장에서는 작업 지침, 담당자, 실행 수단으로 이해하면 됩니다.

워크플로에는 무엇을 조사하고 어떤 결과를 만들지 적습니다. 영상의 설명에서는 경쟁사 자료를 모으고, 조사 결과와 자사 정보를 분석한 뒤, PDF 보고서를 만드는 순서를 예로 듭니다. 이런 지침을 Markdown 문서로 저장하면 다음 실행에서도 참고할 기준이 남습니다.

에이전트인 Claude Code는 지침과 사용 가능한 도구를 읽고 작업을 진행합니다. 도구는 웹사이트에서 정보를 가져오거나 PDF를 만드는 등 개별 작업을 수행하는 Python 스크립트입니다. 시연에서는 Claude Code가 필요한 스크립트를 직접 만들었습니다.

이 구분을 적용하면 수정 요청도 구체적으로 할 수 있습니다. 조사 항목이 부족하면 업무 지침을 고치고, 보고서의 로고가 보이지 않으면 PDF 생성 부분을 살펴보는 식입니다. 제작자는 피드백을 지침과 도구에 반영해 다음 실행을 개선하는 과정을 강조합니다.

시연에서 제작자는 Get Leads with AI라는 사업을 예로 들었습니다. 잠재고객 정보를 수집하고 목록을 만들며, AI로 대규모 맞춤형 연락을 돕는 서비스라고 설명했습니다. 이후 AI가 추가 질문을 하자 주요 고객은 마케팅 대행사, 과금 방식은 크레딧 기반 사용량 과금, 차별점은 여러 기능을 모은 통합 플랫폼이라고 답했습니다.

처음부터 사업 정보가 충분했던 것은 아닙니다. AI는 실행 도중 고객층과 가격 등을 다시 물었고, 답변을 사업 프로필 JSON 파일에 저장했습니다. 제작자는 같은 정보를 매번 설명하지 않도록 프로젝트 안에 보관해 달라고 요청했습니다.

이 장면을 참고하면 준비할 입력이 분명해집니다. 회사 소개뿐 아니라 판매하는 상품이나 서비스, 가격, 주요 고객, 차별점을 함께 정리하는 것입니다. 그래야 경쟁사 목록을 받았을 때 왜 이 회사들이 비교 대상으로 선정됐는지 검토할 기준이 생깁니다.

가상의 적용 예로, 마케팅 대행사가 자사 제안서를 개선하려 한다면 주력 서비스와 고객 유형, 가격 구성, 강점을 먼저 전달할 수 있습니다. 이어 비슷한 고객을 대상으로 하는 경쟁사의 서비스와 홍보 문구를 비교해 달라고 요청하는 방식입니다. 이는 영상의 경쟁사 분석 흐름을 응용한 예시이며, 해당 업종의 성과가 검증됐다는 뜻은 아닙니다.

영상에서는 VS Code에 Claude Code 확장 기능을 설치하고 빈 프로젝트 폴더를 준비했습니다. 여기에 작업 방식을 설명하는 문서를 넣어 업무 지침, 도구, 임시 파일을 나눠 보관할 폴더를 만들었습니다. 그다음 계획 모드에서 경쟁사 분석 업무를 설명했습니다.

요청의 출발점은 회사 로고와 색상, 글꼴을 반영한 PDF였습니다. AI는 경쟁사를 직접 지정할지 자동으로 찾을지, 어떤 정보를 분석할지, 얼마나 자주 실행할지, API 비용은 어느 정도를 고려하는지 질문했습니다. 제작자는 경쟁사 자동 탐색과 월간 실행을 선택했습니다.

계획에는 사업 정보 수집, 경쟁사 탐색, 조사, 분석, PDF 생성 도구가 포함됐습니다. 다만 브랜드 설정에는 제작자가 제공하지 않은 정보가 들어가 있어 수정이 필요했습니다. 제작자는 실제 로고와 브랜드 지침 파일을 넣고, 그 자료에서 색상과 글꼴을 읽어 보고서에 적용하도록 요청했습니다.

계획을 승인한 뒤에는 필요한 프로그램 구성요소를 설치하고 Anthropic과 Firecrawl의 API 키를 설정했습니다. 업무에 적용할 때도 원하는 결과물 설명, AI의 추가 질문에 답변, 계획 검토, 필요한 자료와 연결 정보 준비, 시험 실행의 순서로 진행해볼 수 있습니다. 특히 계획에 적힌 회사 정보와 디자인 기준이 실제로 제공한 자료와 일치하는지 확인하는 과정이 필요합니다.

시연 결과에는 사업 프로필, 경쟁사별 자료, 분석 기록, PDF 보고서가 남았습니다. 보고서는 사업 개요와 경쟁 구도, 경쟁사별 특징, 전략 제안을 담았습니다. 여기서 AI가 제안한 가격이나 사업 방향은 시연에서 생성한 분석 결과이므로, 그대로 적용했을 때 효과가 보장되는 권고로 받아들여서는 안 됩니다.

실행 과정도 한 번에 끝나지 않았습니다. 경쟁사 조사 중 Windows의 문자 인코딩 오류가 발생하자 Claude Code가 스크립트를 수정했습니다. 첫 PDF에서는 제작자가 로고와 차트를 확인하지 못했고, 원인을 조사해 고치도록 다시 요청했습니다.

수정 후 제작자는 새 보고서에서 로고와 가격 분석 차트를 확인했습니다. 이때 기존 조사 데이터를 재사용해 PDF를 다시 만들었습니다. 영상에서 해당 조사 실행 비용은 1.43달러로 표시됐지만, 이는 그 시연의 결과이며 다른 업무에도 같은 비용이 든다는 기준은 아닙니다.

사업자가 확인할 대상은 실행 완료 메시지와 실제 보고서 모두입니다. 비교 대상이 적절한지, 분석이 우리 사업 정보를 반영했는지, 필요한 설명이 충분한지 읽어보는 것이 좋습니다. 로고와 차트가 제대로 보이는지도 최종 PDF를 열어 확인한 뒤, 부족한 부분을 수정 요청으로 남깁니다.

제작자는 업무를 반복하고 피드백을 주면서 작업 방식이 개선된다고 설명합니다. 시연에서 확인된 것은 사업 정보를 파일에 저장하고, 오류가 난 도구와 PDF 생성 부분을 수정하는 과정입니다. 실제 도입을 판단할 때는 원하는 자료가 남는지, 수정 사항이 다음 결과에 반영되는지 살펴보는 편이 구체적입니다.

처음에는 경쟁사 조사 한 건처럼 결과를 직접 읽고 판단할 수 있는 업무를 골라보세요. 우리 사업 소개, 비교할 항목, 원하는 보고서 구성을 한 문서에 적는 것이 첫 행동입니다. 그 문서를 바탕으로 실행 계획을 요청하고, 첫 보고서에서 어떤 결정을 내릴 수 있어야 하는지부터 확인해보시기 바랍니다.
