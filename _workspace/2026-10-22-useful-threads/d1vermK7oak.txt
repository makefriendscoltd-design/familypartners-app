업무용 프로그램 수정, Claude Code로 맡기고 결과까지 확인하는 방법

업무용 프로그램에 오류가 생겼을 때 AI가 수정 코드를 알려줘도 일이 끝난 것은 아닙니다. 코드를 어느 파일에 넣을지 찾고, 직접 반영한 뒤, 원래 업무가 제대로 돌아가는지 확인해야 합니다. 사업자가 작은 프로그램을 관리하면서 이 과정을 반복하고 있다면, AI에게 답을 받는 것과 실제 수정을 맡기는 것의 차이를 살펴볼 필요가 있습니다.

이번 영상은 Claude Code가 프로젝트 파일을 읽고 수정한 뒤 실행 결과를 확인하는 과정을 소개합니다. 여기서는 설치 방법보다 업무를 맡기는 기준과 검증 순서에 초점을 맞춰 살펴보겠습니다.

영상에서 설명하는 Claude Code는 프로젝트 안에서 파일을 읽고, 필요한 내용을 수정하며, 터미널 명령을 실행하는 도구입니다. 채팅창에 코드를 복사해 질문하고 답변을 다시 옮기는 대신, 프로젝트 폴더를 작업 공간으로 삼습니다. 관련 내용을 찾고 행동한 뒤 결과를 점검하며, 문제가 남으면 다시 수정하는 방식입니다.

기존 프로그램의 오류를 찾거나 코드를 반복해서 고칠 때 활용할 만한 방식입니다. 다만 무엇이 정상인지 알려주지 않으면 사업자가 원하는 완료 상태와 AI가 판단한 완료 상태가 달라질 수 있습니다. 수정할 대상과 함께 어떤 입력에서 어떤 결과가 나와야 하는지도 정해두는 것이 좋습니다.

제작자는 요청을 처음 합류한 동료에게 일을 설명하듯 구체적으로 쓰라고 권합니다. 문제가 나타나는 상황, 관련 파일, 바꾸면 안 되는 부분, 완료 조건을 전달하라는 뜻입니다. 관련 파일을 이미 알고 있다면 직접 지정해 조사 범위를 좁히라고 설명합니다.

가상의 적용 예시로, 내부 주문 프로그램에서 할인 금액이 잘못 계산되는 상황을 생각해보겠습니다. 이때는 할인 코드를 입력한 주문에서 어떤 오류가 나타나는지 설명하고, 기존 세금 계산은 유지하면서 할인 계산을 고쳐달라고 요청할 수 있습니다. 수정 후에는 같은 주문을 다시 실행해 정상 금액이 나오는지 확인하도록 요구하는 방식입니다.

영상에서 권하는 진행 순서는 코드 탐색, 계획, 수정, 테스트, 변경 기록 저장입니다. 처음에는 관련 코드의 흐름을 설명하게 하고, 이어서 파일을 바꾸지 않는 계획 모드에서 수정안을 검토합니다. 사업자는 이 단계에서 요청한 범위를 벗어나지 않았는지 확인한 뒤 구현을 맡기면 됩니다.

영상의 Python 데모 앱에는 SAVE10 할인 코드가 등장합니다. 할인율을 저장한 값 10은 10%를 뜻하지만, 계산 코드가 이를 그대로 곱하면서 70달러 주문에 700달러 할인을 적용하는 오류가 있었습니다. Claude Code는 할인율을 100으로 나누고, 할인액이 상품 합계를 넘지 않도록 제한하는 수정을 제안합니다.

시연에서는 수정 후 테스트 8개가 통과했습니다. 그중에는 70달러 주문에 SAVE10을 적용하면 할인 후 63달러가 되고, 세금을 포함하면 68.04달러가 되는지 확인하는 검사가 포함됐습니다. 제작자는 테스트 결과를 본 뒤 앱도 직접 실행해 68.04달러가 출력되는지 다시 확인합니다.

업무에 적용할 때도 두 번의 확인을 거치는 편이 좋습니다. 테스트에서 정한 조건을 통과했는지 살피고, 실제 프로그램에서도 예상한 결과가 나오는지 대조하는 것입니다. 영상의 결과는 해당 데모 앱에서 확인한 사례이므로, 자신의 프로그램에서도 대표 입력과 예상 결과를 따로 준비해야 합니다.

제작자는 변경 내용을 저장하기 전 수정된 파일도 검토합니다. 이 사례에서는 계산 코드와 테스트 파일을 확인했는데, 업무에 적용할 때도 요청한 수정 외에 다른 부분까지 바뀌지 않았는지 살펴보는 기준으로 삼을 수 있습니다.

같은 프로그램을 계속 관리한다면 테스트 방법이나 수정 규칙을 매번 설명하는 일도 생깁니다. 영상은 프로젝트의 공통 지침을 담는 CLAUDE.md를 소개합니다. 테스트 실행 명령, 중요한 폴더, 코드 작성 규칙처럼 세션마다 필요한 정보를 기록하고, 막연한 표현보다 확인 가능한 지시를 쓰라고 권합니다.

예를 들어 오류를 수정할 때 같은 문제가 다시 생기는지 확인할 테스트를 추가하라는 규칙을 남기는 방식입니다. 문서에 모든 설명을 넣기보다는 자주 필요한 지침을 간결하게 적고, 긴 참고 자료는 별도로 연결하라는 것이 제작자의 조언입니다. 업무에 적용한다면 반복해서 정정했던 내용부터 기록하는 편이 좋겠습니다.

특정 작업의 순서는 스킬로 묶을 수 있다고 설명합니다. 영상에서는 최근 코드 변경 기록을 읽고 고객이 이해할 수 있는 업데이트 안내문을 작성하는 스킬을 시연합니다. 입력은 변경 기록이고 확인할 결과물은 고객용 안내문이므로, 사업자는 실제로 달라진 기능이 정확히 반영됐는지 검토하면 됩니다.

여러 파일을 읽는 조사나 별도 검토가 필요할 때는 하위 에이전트를 활용하는 방법이 나옵니다. 하위 에이전트는 별도의 대화 공간에서 작업하고 핵심 결과를 돌려줍니다. 영상의 검토 사례에서는 알 수 없는 할인 코드를 프로그램이 별도 안내 없이 무시한다는 점을 지적했는데, 사업자는 이를 보고 고객에게 오류 안내가 필요한지 판단할 수 있습니다.

파일 수정 뒤 정해진 검사를 실행하는 데는 훅을 소개합니다. 훅은 특정 시점에 자동으로 실행되는 명령으로, 영상에서는 파일을 편집한 직후 코드 형식을 정리하는 예시를 보여줍니다. 반복해서 잊는 절차에 적용할 수 있지만 사용자 권한으로 실행되므로, 어떤 명령이 등록됐는지 이해하고 검토하라는 주의도 함께 나옵니다.

외부 자료가 필요할 때는 MCP로 도구를 연결하는 방법을 설명합니다. Sentry의 오류 정보를 읽거나 Playwright로 브라우저를 조작해 웹 앱을 확인하는 사례가 등장합니다. 업무에 적용한다면 먼저 확인할 오류나 화면 동작을 정하고, 그 작업에 필요한 도구부터 연결하는 편이 좋겠습니다.

권한과 복구 범위도 함께 판단해야 합니다. 제작자는 Claude Code의 되돌리기가 파일 편집을 추적하지만, 명령 실행으로 생긴 파일 삭제나 데이터베이스 변경까지 되돌리지는 못한다고 설명합니다. 수정을 맡길 때는 변경 내용뿐 아니라 실행할 명령도 검토해야 하는 이유입니다.
